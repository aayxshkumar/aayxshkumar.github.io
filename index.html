lob-engine

A limit order book with price-time priority. Orders come from a pre-allocated pool, and each price level keeps its orders in an intrusive list, so adding an order never allocates and cancelling one is O(1). v1 replaced the std::map price levels with two flat arrays indexed by price tick, plus a bitset of which levels are non-empty. v2 replaced std::unordered_map for the id lookup with a flat open-addressing table. Every commit to it is co-authored with Claude Code (how I use it).

Both steps had a catch. The first array version was slower on sparse books, because of a bug that walked the whole 65,536-tick band. And the benchmark numbered orders 1, 2, 3, which flattered the id lookups: with random-looking ids v1, on std::unordered_map, lost 13%, and v2, on its own table, 14%. The write-up has both stories.

Testing

Every operation is checked against a deliberately naive reference book, trades and depth at every price, over 20,000 random steps for each of 10 seeds, and the old and new books run the same 22 tests. My first version of that test passed with a bug planted in it: the random flow crossed the spread so often that queues never formed, so priority bugs had nowhere to show up. Once I biased the flow towards passive orders and added same-price size increases, the tests caught every bug planted to test them, Planted in the C++: 5 in the matching rules, 4 in the array book, 3 in the bitset, 4 in the id table. The 51 tests and the 20,000-step differential test caught each one. Full receipt. ⁠so ⁠far.

Five of them are in the table below; with JavaScript on, you can step through each one. It’s a JavaScript port of the matching rules replaying a short hand-written scenario; the C++ and the 20,000-step test are on GitHub.
