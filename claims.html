Run it

The flags are reconstructed from bench/order_book_bench.cpp at 2178cef; the README says only “median of 3 repetitions”. tools/run_bench.sh, added later, runs every benchmark this way and keeps the output under bench/results/.

v0 and v2, the mixed workload, at 2178cef

git checkout 2178cef
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build -j
./build/lob_bench \
  --benchmark_filter='^(v0_map|v2)/mixed/1000000/262144$' \
  --benchmark_repetitions=3

v1, the mixed workload, at ffe9956 (v1 is no longer in the tree)

git checkout ffe9956
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build -j
./build/lob_bench \
  --benchmark_filter='^v1_array/mixed/1000000$' \
  --benchmark_repetitions=3

The replay, which runs 5 repetitions itself; it needs your own recording

python3 tools/record_binance.py BTCUSDT 1200 data/btcusdt.lobrec
./build/lob_replay data/btcusdt.lobrec

What each status means

public at a commit
The raw data, or the code that produces the number, is in lob-engine at that commit.
rerun public at a commit
The published number’s own output wasn’t kept, but a rerun of identical code on the same machine is committed, with its JSON. The reruns differ from the published medians by −9% to +4% (the v0 replay moved most); within one session, repetitions vary by 0.1–5.5% (the cv rows in bench.json). The ledger gives both.
README only
The README states it, and no command in today’s tree reproduces it exactly: v1 is only in history, and the replay needs a recording that isn’t published.
anyone with a Mac can check it
One command on your own machine settles it.
employer figure
The Airbus numbers. They come from my work there and can’t be published; nothing here pretends otherwise.
